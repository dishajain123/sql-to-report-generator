## Purpose Summary

This procedure determines and updates the Special Mention Account (SMA) classification for loan and advance accounts based on their overdue and overdrawn status, in line with regulatory asset quality norms. It ensures that accounts are correctly marked as SMA-0, SMA-1, or SMA-2 based on the maximum number of days past due (DPD) across several delinquency dimensions, and records the reasons for any downgrade. The process also maintains historical movement records for both account and customer asset classifications, supporting audit and compliance requirements.

## Step-by-Step Logic Flow

1. Retrieve the process date corresponding to the provided time key.
2. Identify accounts with significant overdue or overdrawn status for further SMA evaluation.
3. Reset any negative delinquency counters (DPD fields) to zero to ensure data integrity.
4. Calculate the maximum DPD value for each account across all relevant delinquency types.
5. Assign the appropriate SMA classification (SMA-0, SMA-1, SMA-2) to each account based on the maximum DPD value.
6. Record the specific reason for SMA downgrade, depending on which delinquency type triggered the classification.
7. Update the SMA effective date to reflect the start of the delinquency period.
8. Flag accounts as being under SMA monitoring.
9. Aggregate SMA classifications at the customer and group (UCIF) level for consolidated reporting.
10. Update customer-level SMA status and effective dates based on the highest risk among linked accounts.
11. Maintain movement history for both account and customer asset classifications, closing previous records and opening new ones as needed.
12. Update descriptive labels for customer and account movement statuses to reflect current asset classification.
13. Increment process completion counters and update process status for monitoring and dashboard reporting.

## Calculations / Formulas

- **Maximum DPD (DPD_Max):** For each account, DPD_Max is set to the highest value among DPD_IntService, DPD_NoCredit, DPD_Overdrawn, DPD_Overdue, DPD_Renewal, and DPD_StockStmt.
- **SMA Classification:** SMA_CLASS is set to 'SMA_0' if DPD_Max is between 1 and 30, 'SMA_1' if between 31 and 60, and 'SMA_2' if between 61 and 90 or greater than 90.
- **SMA Reason:** SMA_REASON is set based on which DPD category matches DPD_Max and the facility type, indicating the primary cause of downgrade.
- **SMA Effective Date:** SMA_DT is calculated as the process date minus DPD_Max plus one, representing the start date of the delinquency.
- **Customer/Group SMA Class Key:** SMA_CLASS_KEY is set to the highest numeric value among linked accounts' SMA_CLASS (SMA_0=1, SMA_1=2, SMA_2=3).
- **Movement To Date:** MovementToDate is set to one day before the process date when closing a movement record.
- **Process Run Count:** COUNT is incremented by 1 or set to 1 if previously null, tracking the number of times the process has run.

## Exception Handling Behavior

If an error occurs during the SMA marking process, the system updates the process status to indicate failure, records the error date and description, and increments the process run count. This ensures that operational issues are logged for review and resolution.
